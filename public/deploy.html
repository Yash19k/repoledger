Deploy RepoLedger on AWS, step by step

The big picture

One EC2 server runs two containers. The database is private. Secrets come from Parameter Store.

The internet reaches only ports 80 and 443 on the server. The database accepts connections only from machines in the server's security group.

Concepts to understand first

You deploy a long-running server, not functions. Every later step uses these ideas.

Why EC2 and not Lambda

RepoLedger is a classic long-running server. It keeps rate limits and lookup progress in memory, runs hourly cleanup with setInterval, and expects exactly one instance. Lambda starts and stops copies of your code per request, which breaks all three.

OptionYou manageFits as written?Cost
EC2 + Docker (this guide)The VM, Docker, HTTPS proxyYesFree-tier instance type
Lambda + API GatewayOnly codeNeeds a rewriteNear zero
App Runner / ECS FargateOnly the containerYesNo free tier
Elastic BeanstalkLittleYesSame as EC2, hides the learning

The AWS building blocks

Region
ap-south-1 in this guide. Keep the console's region picker on it, or your resources seem to vanish.
VPC
Your private network in AWS. Each region has a default VPC with public subnets; we use it.
EC2 instance
A virtual machine rented by the hour. Its size is the instance type, its OS image is the AMI.
EBS volume
The instance's disk. Survives reboots, deleted when the instance is terminated.
Security group
A firewall listing allowed inbound traffic. A rule's source can be another group: "anything wearing that group".
Elastic IP
A fixed public IPv4 address. The GitHub App's callback URL needs one that never changes.
RDS
AWS runs PostgreSQL for you, with backups and patching. You connect to its endpoint hostname.
IAM role
Permissions a service wears. An EC2 instance with a role gets short-lived credentials, so no keys sit on disk.
Parameter Store
Free key-value config store. SecureString values are encrypted with KMS.
CloudWatch and Budgets
Metrics, logs and alarms; Budgets emails you when spending passes a limit.
Image vs container
The Dockerfile is a recipe, docker build bakes an image, docker run starts a container.
Reverse proxy
Receives internet traffic and forwards it to the app. Caddy also fetches and renews free HTTPS certificates.

Why HTTPS is required. RepoLedger marks its session cookie Secure when PUBLIC_URL starts with https://, and GitHub sign-in redirects back to that URL. Certificates need a name, not a bare IP: sslip.io is free public DNS where 13-233-10-20.sslip.io resolves to 13.233.10.20, so you need no domain.

0

Account safety first

Learn: budgets, MFA, why you never work as root

A server and a database bill every hour they exist, unlike Lambda. Set a spending alarm before you create anything.

  1. Check your free tier. Billing and Cost Management → Free Tier. Newer accounts get a credit-based free plan; older ones have the 12-month free tier (750 h/month of t3.micro and db.t4g.micro).
  2. Create a budget. Billing → Budgets → Create budget → Monthly cost budget, $5, your email. AWS emails you at 85% and 100%.
  3. Don't use the root user. Sign in as an IAM user (or IAM Identity Center user) with MFA turned on.
  4. Switch the region to ap-south-1 in the console's top-right picker and keep it there.
  5. Local tools: Git and an SSH client. Windows includes OpenSSH: check with ssh -V in PowerShell.macOS and Linux include it: check with ssh -V. The AWS CLI comes preinstalled on the server.
  6. Get the code on GitHub. Fork the RepoLedger repository (source) and put your fork's clone URL in Your values. The server clones it in Step 4; a public fork clones without credentials.
  7. Get a lookup token: GitHub → Settings → Developer settings → Fine-grained tokens, public repositories read-only, no other permissions.

The budget, MFA and a non-root user are the three habits every AWS engineer sets up on day one. Most surprise bills come from a forgotten resource, not traffic.

Create the firewalls

Learn: security groups, group-to-group rules, stateful firewalls

EC2 → Network & Security → Security Groups → Create security group, default VPC.

repoledger-web-sg · for the server

TypePortSourceWhy
SSH22My IPOnly your computer can log in
HTTP80Anywhere-IPv4Let's Encrypt checks it; Caddy redirects it to HTTPS
HTTPS443Anywhere-IPv4The website

repoledger-db-sg · for the database

TypePortSourceWhy
PostgreSQL5432repoledger-web-sgOnly machines wearing the web group connect

Security groups are stateful: replies to allowed traffic leave automatically, so outbound stays "all traffic". The database rule names a group, not an IP, so a replacement server with the same group still works. "My IP" changes when your network does; if SSH suddenly times out, check that rule first.

TLS to the database. RDS for PostgreSQL 15+ requires encryption, which RepoLedger does by default. To also verify the server's certificate, the app reads DATABASE_SSL_CA. You download AWS's CA bundle onto the server in Step 7.

4

Connect and install Docker

Learn: SSH keys, Linux services, swap memory

SSH refuses a key that other users can read, so lock it down first.

PowerShell · your computer
mkdir $HOME\.ssh -Force
move $HOME\Downloads\repoledger-key.pem $HOME\.ssh\
icacls "$HOME\.ssh\repoledger-key.pem" /inheritance:r /grant:r "$($env:USERNAME):(R)"
ssh -i $HOME\.ssh\repoledger-key.pem ec2-user@13.233.10.20
Terminal · your computer
mkdir -p ~/.ssh
mv ~/Downloads/repoledger-key.pem ~/.ssh/
chmod 400 ~/.ssh/repoledger-key.pem
ssh -i ~/.ssh/repoledger-key.pem ec2-user@13.233.10.20

Type yes at the fingerprint question. Now you're on the server:

bash · server
# 1. Update the OS and install Docker, Git and cron
sudo dnf update -y
sudo dnf install -y docker git cronie
sudo systemctl enable --now docker crond   # start now and on every boot
sudo usermod -aG docker ec2-user           # run docker without sudo

# 2. Docker Compose plugin (not packaged on AL2023)
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

# 3. 1 GiB swap so npm installs never run out of memory
sudo dd if=/dev/zero of=/swapfile bs=1M count=1024
sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab

# 4. Get the code
git clone https://github.com/your-name/repoledger.git ~/repoledger

Type exit and SSH in again so the docker group applies. Then docker version and docker compose version must both answer without sudo.

systemctl enable --now is how Linux services survive reboots. Swap is disk used as overflow memory: slow, but it turns an out-of-memory crash into a short slowdown.

Create the production GitHub App

Learn: OAuth callbacks, app private keys, keeping dev and prod apart

Use a separate app for production. If you also run RepoLedger locally, that app keeps working, and a leaked dev key can't touch production. Don't use npm run create-app here: it overwrites your local .env.

App names are unique across all of GitHub, so pick one nobody else has, such as RepoLedger-yourname.

GitHub → Settings → Developer settings → GitHub Apps → New GitHub App:

FieldValue

After Create GitHub App: copy the App ID and Client ID, note the slug from github.com/apps/<slug>, generate a client secret (shown once) and a private key (a .pem file downloads).

Each setting must fit on one line. RepoLedger turns a literal \n back into line breaks, so flatten the key and copy it:

PowerShell · your computer
((Get-Content $HOME\Downloads\repoledger*.private-key.pem -Raw).Trim() -replace "\r?\n", '\n') | Set-Clipboard
Terminal · your computer
awk -v ORS='\\n' '1' ~/Downloads/repoledger*.private-key.pem | pbcopy
# Linux: replace pbcopy with  xclip -selection clipboard

The pattern matches a key whose app name starts with "RepoLedger". If you named the app differently, or have several keys in Downloads, use the exact file name.

The private key lets anyone act as your app on every account that installed it. It never goes in Git, chat or a screenshot. Delete the downloaded .pem once it's stored in Step 6.

6b · IAM role for the server

IAM → Roles → Create role → AWS service → EC2, no managed policies, name repoledger-ec2-role. Then Add permissions → Create inline policy → JSON, named read-repoledger-params:

IAM policy JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["ssm:GetParametersByPath", "ssm:GetParameter"],
      "Resource": [
        "arn:aws:ssm:ap-south-1:123456789012:parameter/repoledger",
        "arn:aws:ssm:ap-south-1:123456789012:parameter/repoledger/*"
      ]
    }
  ]
}

Attach it: EC2 → repoledger-server → Actions → Security → Modify IAM role. Then test on the server; the first command should mention assumed-role/repoledger-ec2-role:

bash · server
aws sts get-caller-identity
aws ssm get-parameter --region ap-south-1 --name /repoledger/PUBLIC_URL --query Parameter.Value --output text

This is least privilege: the server may read only /repoledger/*. No access keys exist on disk; the instance gets temporary credentials from its metadata service and AWS rotates them. If you see AccessDenied on kms:Decrypt, add that action to the policy.

7

Run it with Compose and Caddy

Learn: Docker Compose, private container networks, automatic HTTPS

There is no separate frontend deploy: Express serves public/ itself. Deployment files live in ~/deploy, outside the Git checkout, so git pull never touches them.

7a · Settings file from Parameter Store

bash · server
mkdir -p ~/deploy && cd ~/deploy
curl -so rds-ca.pem https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem
touch rds-ca.pem   # unused on Supabase, but compose.yaml mounts it

cat > fetch-env.sh <<'EOF'
#!/bin/bash
set -euo pipefail
cd ~/deploy
aws ssm get-parameters-by-path --region ap-south-1 --path /repoledger/ --with-decryption \
  --query 'Parameters[].[Name,Value]' --output text |
while IFS=$'\t' read -r name value; do
  printf '%s=%s\n' "${name##*/}" "$value"
done > .env.new
chmod 600 .env.new && mv .env.new .env
echo "Wrote $(wc -l < .env) settings to ~/deploy/.env"
EOF
chmod +x fetch-env.sh && ./fetch-env.sh

${name##*/} strips everything up to the last /, so /repoledger/PUBLIC_URL becomes PUBLIC_URL.

7b · Caddyfile and compose.yaml

bash · server
cat > Caddyfile <<'EOF'
13-233-10-20.sslip.io {
	reverse_proxy web:8600
}
EOF

cat > compose.yaml <<'EOF'
services:
  web:
    image: repoledger:latest
    env_file: .env
    restart: unless-stopped
    volumes:
      - ./rds-ca.pem:/app/rds-ca.pem:ro
    logging:
      driver: json-file
      options: { max-size: "10m", max-file: "3" }

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - web

volumes:
  caddy_data:
  caddy_config:
EOF

Only Caddy publishes ports. Port 8600 exists only on Compose's private network, where Caddy finds the app by its service name web, so nobody can bypass HTTPS. With one proxy in front, RepoLedger's TRUST_PROXY default is already right and rate limits see real visitor IPs.

7c · Build, create tables, start

bash · server
cd ~/repoledger && docker build -t repoledger:latest . && cd ~/deploy
docker compose run --rm web npm run init-db    # safe to repeat: only adds what's missing
docker compose up -d
docker compose ps                              # both "running"
docker compose logs -f                         # Ctrl+C to stop following

Optional: bring existing data across. If you already ran RepoLedger on Supabase, this keeps traffic history GitHub no longer has. Run it before init-db, with Supabase's Session pooler URL; the transaction pooler can't run pg_dump.

bash · server
docker run --rm postgres:17 pg_dump --no-owner --no-privileges --schema=public \
  "SUPABASE_SESSION_POOLER_URL" > dump.sql
docker run --rm -i postgres:17 psql "RDS_DATABASE_URL" < dump.sql
rm dump.sql   # contains session hashes and stats

Look for RepoLedger is running and Caddy's certificate obtained successfully (about 30 seconds). Then open https://13-233-10-20.sslip.io.

No certificate? Ports 80 and 443 are blocked, or the Caddyfile host doesn't match the Elastic IP. sslip.io shares Let's Encrypt's weekly limits with other users; if issuance is refused, a free DuckDNS subdomain or your own domain works the same way.

Schedule the collector

Learn: cron syntax, why private databases change where jobs run

GitHub Actions runners live on the internet, and your database deliberately doesn't, so the collector moves onto the server. Test once, then schedule:

bash · server
cd ~/deploy && docker compose run --rm web npm run collect

(crontab -l 2>/dev/null; echo '15 */6 * * * cd /home/ec2-user/deploy && /usr/bin/docker compose run --rm web npm run collect >> /home/ec2-user/collect.log 2>&1') | crontab -
crontab -l

If you turned on GitHub Actions in your fork, disable the scheduled one: Actions → Collect GitHub stats → ··· → Disable workflow, so two collectors don't run.

A cron line has five time fields: minute, hour, day, month, weekday. 15 */6 * * * means "minute 15 of every 6th hour". Server time is UTC.

Supabase is reachable from the internet, so the GitHub Actions workflow that ships in the repository can keep collecting:

  1. Forks start with workflows turned off. Open your fork's Actions tab and enable them.
  2. Add the repository secrets DATABASE_URL, APP_ID and APP_PRIVATE_KEY (Settings → Secrets and variables → Actions), using the production app from Step 5.
  3. Run it once from Actions → Collect GitHub stats → Run workflow.

GitHub pauses scheduled workflows in public repositories after 60 days without activity. If collection stops, any commit or re-enabling the workflow restarts it.

Verify, debug and monitor

Done means all six checks pass, including a reboot.

When something is wrong

Start with docker compose ps and docker compose logs --tail 100 web in ~/deploy. After changing a parameter, run ./fetch-env.sh && docker compose up -d.

SSH times out

Your public IP changed. Fix: set the SSH rule in repoledger-web-sg back to My IP.

UNPROTECTED PRIVATE KEY FILE

Other users can read the key. Fix: re-run the icaclschmod 400 line from Step 4.

Build killed, exit code 137

Out of memory. Fix: check swap is on with free -h.

AccessDenied from aws ssm

Role not attached, or wrong account ID or region in the policy. Fix: recheck Step 6b.

App exits: DATABASE_URL must be set

.env is empty or missing. Fix: ./fetch-env.sh then docker compose up -d.

Database connection timeout

DB security group rule missing, or wrong endpoint. Fix: repoledger-db-sg must allow 5432 from repoledger-web-sg.

password authentication failed

Wrong password, or a special character not URL-encoded. Fix: correct /repoledger/DATABASE_URL, re-fetch, restart.

unable to get local issuer certificate

rds-ca.pem missing or wrong path. Fix: ls -l ~/deploy/rds-ca.pem; DATABASE_SSL_CA must be /app/rds-ca.pem.

502 Bad Gateway

Caddy is up but the app crashed. Fix: read docker compose logs web.

Browser warns about the certificate

Caddy couldn't get one. Fix: are ports 80 and 443 open? Does the Caddyfile host match the Elastic IP?

redirect_uri is not associated with this application

The app's callback URL differs from PUBLIC_URL. Fix: make both exactly https://13-233-10-20.sslip.io, no trailing slash.

Sign-in returns but you're not signed in

PUBLIC_URL is http:// or a different host, so the cookie is rejected. Fix: correct it, re-fetch, docker compose up -d.

Alarms worth setting

  • Auto-recovery: instance → Status checks → Actions → Create status check alarm, on System status check failed, action Recover, and notify an SNS topic with your email subscribed.
  • Database disk: CloudWatch alarm on repoledger-db FreeStorageSpace below 2 GB.
  • CPU credits: watch CPU credit balance; stuck near zero means the instance is too small.

Deploying an update

After you push to your fork, run this on the server. Save it once as ~/deploy/update.sh and chmod +x it.

~/deploy/update.sh
#!/bin/bash
set -euo pipefail
cd ~/repoledger && git pull --ff-only
docker build -t repoledger:latest .
cd ~/deploy && ./fetch-env.sh
docker compose run --rm web npm run init-db   # applies schema changes
docker compose up -d                          # swaps to the new image
docker image prune -f                         # old images can't fill the disk

Tearing it all down

  1. EC2 instance: Instance state → Terminate.
  2. Elastic IP: Actions → Release.
  3. RDS: Actions → Delete; untick Retain automated backups.
  4. Security groups: repoledger-db-sg first, then repoledger-web-sg.
  5. Parameters under /repoledger/, the IAM role, alarms and SNS topic.
  6. GitHub: delete the production app or keep it, and disable the collect workflow in your fork.
